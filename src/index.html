Le traitement n'est pas le même selon la machine. Choisis d'abord, tu ouvriras ta ROM ensuite.

En génération 3, le maximum atteignable est 1/256 : la constante comparée tient sur un octet d'instruction THUMB. Une valeur plus basse sera ramenée à ce plafond, et le logiciel te dira exactement ce qu'il a appliqué.

Un seul export pour les deux traitements : le taux de shiny et les rencontres sauvages réglées dans l'onglet Randomizer partent ensemble dans le même fichier. Les boutons sont identiques dans les deux onglets.

Chaque espèce d'origine est remplacée par la même espèce partout dans le jeu. Les Roucool restent des Roucool, mais deviennent tous autre chose.

Même graine + même ROM = ROM identique au bit près. Donne la même graine à tous les participants pour une race équitable, ou une graine différente à chacun pour une race à l'aveugle.

Les badges désynchronisent le scénario. Des personnages attendront que tu n'aies pas encore tel badge, certains dialogues seront incohérents. Sans importance pour une race où personne ne suit l'histoire, mais il faut le savoir. Les CT et CS sont ajoutées en silence : aucun message ne s'affiche malgré les 58 objets.

Maximum 255 par objet. Le jeu ne lit qu'un octet pour la quantité : demander 800 donne 32 (800 − 3×256). Les valeurs plus grandes sont ramenées à 255. Mettre 0 retire l'objet de la dotation. Le message affiché à l'écran continuera d'annoncer cinq Poké Balls : seul le texte d'origine subsiste, les objets réellement reçus sont bien ceux-ci.

Le taux de shiny réglé dans l'onglet précédent est appliqué dans le même fichier. Si la table de rencontres reste introuvable, l'export se fait quand même avec le seul taux de shiny.

Le moteur est téléchargé depuis le dépôt officiel du projet, au premier usage. Il n'est pas livré avec l'application : l'archive contient un environnement Java complet, et sa licence impose des obligations de redistribution qu'on évite en te laissant le récupérer à la source. Rien n'est envoyé nulle part, et aucun jeu n'est téléchargé.

Deux joueurs qui saisissent la même graine sur la même ROM obtiennent exactement la même randomisation. C'est ce qui rend une course comparable.

L'ordre n'est pas négociable. Le randomizer reconstruit la ROM entière, arm9 compris. Appliqué après notre modification, il l'effacerait sans le moindre message. Ce bouton fait donc les deux dans le bon sens : randomisation d'abord, taux de shiny ensuite.
